## Validated match table

Location: `data/validated/matches/season=<YYYY>/part-0.parquet` (also contains the `season` column). One row per singles match. DuckDB view: `matches`.

Player A and player B are assigned by `sha256(match_id)` (first byte even -> lower ID is A), which is deterministic and independent of the result. Columns prefixed `player_a_` / `player_b_` refer to those players; the source's winner/loser perspective survives only in `winner_id`, `player_a_won` and `score`.

## Quarantine table

Location: `data/quarantine/matches.parquet`. DuckDB view: `quarantine`. Same columns as the validated table (any of which may be null, since quarantined rows can lack required values), plus:

| column | type | description |
|---|---|---|
| `quarantine_reasons` | List(string) | Sorted error codes that sent the row to quarantine |
| `quarantine_categories` | List(string) | Sorted categories of those codes (schema, identity, stats, duplicate, conflict, ...) |
| `duplicate_of` | string | For duplicate_record: match_id of the kept first occurrence |
| `raw_record` | string | JSON of the original 49 source fields exactly as read (whitespace-trimmed strings) |

## `match_status` values

| value | meaning |
|---|---|
| `completed` | score is a complete list of sets |
| `retired` | score contains RET: a player retired during the match |
| `walkover` | W/O or Walkover: not played; never use as a played result |
| `default` | DEF / Def.: a player was defaulted |
| `abandoned` | ABD / ABN: match abandoned |
| `unfinished` | 'Played and unfinished' / 'In Progress' |
| `unknown` | score empty, 'NA', 'UNK', garbled with '?', or otherwise unparseable |

`round_order` sorts matches within an event. It is an ordinal, not a time: RR matches of one event share a value, and qualifying-round order relative to main-draw rounds is approximate.

## Temporal semantics (leakage)

- The source has **no match dates or times**. `match_date` and `match_start_time` are always null and are never inferred from `tournament_date`. `time_precision` is `tournament_week` for every row.
- `tournament_date` is the event start (usually a Monday); every match of an event shares it. Order matches with `(tournament_date, tournament_id, round_order)`; matches in the same round of the same event are not ordered relative to each other.
- Ranks, ranking points, seeds, entry and age are as of `tournament_date`, i.e. known before the event. Height and hand are biographical values of unknown measurement date.
- Serve statistics describe the match itself: they are outcomes, never pre-match features.
